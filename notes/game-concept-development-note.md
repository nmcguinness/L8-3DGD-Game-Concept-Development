# Ten Commandments of Concept Development

1. The theme lives in the rules, not the paint.
2. Name the verb before you build the world.
3. If swapping the theme changes nothing, start again.
4. Write three versions before you choose one.
5. Choose the feeling first, then the mechanic.
6. Ambition must be justified; risk must be named.
7. Every character detail must be playable.
8. A limit says more than an ability.
9. The mechanic is the pressure that reveals the character.
10. Tell the story through the world, not around it.

---

# Introduction

Every year, first drafts of game concepts fail in the same three ways:

- The theme sits on top of a standard mechanic instead of shaping it.
- The concept plays it safe: single-player, keyboard and mouse, a familiar genre template.
- The player character is a costume, with no wants, limits or history.

None of these is a lack of talent. Each one comes from answering the parts of a concept separately. You pick a theme, then a mechanic, then a platform, then a character, and each gets a surface answer because nothing forces them to depend on each other.

This note gives you four tools that force those connections. You will use all of them in the paired lab, and the results feed directly into your individual concept questionnaire, which the supervision panel reviews in Week 3.

If you have written a game design document before, the ideas are familiar. The difference here is that every answer must be tested against the others.

## 1. Make the theme drive the mechanic

### 1.1 Pain point

A concept for a time-themed game reads: "A platformer where a timer counts down and you have to reach the end before time runs out." Swap *time* for *ghosts*, *weather* or *debt*, and the game plays exactly the same. The theme is decoration.

### 1.2 Concept

A game is what the player *does*. Jesper Juul (2005) describes games as **real rules** wrapped in a **fictional world**. A superficial theme lives only in the fiction: the title, the art, the cutscenes. A strong theme reaches into the rules.

To reach the rules, name the **core verb**: the main action the player repeats, written as one sentence.

> The player [verb] [object] in order to [goal], and this expresses the theme because [reason].

Then apply the **substitution test**: swap your theme for a different one and ask what breaks.

| Result | What it means | What to do |
| :- | :- | :- |
| Nothing changes | Theme is decoration | Rebuild the core verb around the theme |
| Only story and art change | Theme is surface | Find one rule of play that depends on the theme |
| Core rules stop working | Theme drives mechanic | Keep going; this is the target |

Rules also make arguments of their own. Ian Bogost (2007) calls this **procedural rhetoric**. In *Papers, Please*, you never read a lecture about bureaucracy and complicity; the stamping rules and the wage system make that argument for you.

The opposite failure is **ludonarrative dissonance**, a term coined by Clint Hocking (2007) about *BioShock*: the story says one thing while the rules reward another.

### 1.3 Mental model

Read it as: *strip out all art, text and sound. What do the rules alone say about the theme?* If the answer is "nothing", the theme is not yet in the game.

### 1.4 Worked example

*Minit* gives the player a life of sixty seconds. Every run ends, and progress comes from learning what can be done in the time available.

- Core verb: the player *spends* a fixed allowance of time to act.
- Substitution test: swap time for any other theme and the core loop collapses.
- Procedural rhetoric: the rules argue that time is finite and that knowledge is what carries over.

<!-- IMAGE: "Minit game screenshot sixty second timer black and white" -->

*Outer Wilds* goes further. Its twenty-two-minute loop is not a timer bolted onto exploration; the whole solar system is designed around what can be seen, reached and understood before the loop resets.

### 1.5 Pitfalls

- A countdown timer is not a time mechanic. It is a pressure device that works with any theme.
- Setting is not theme. A haunted forest is a location; a thin place is a relationship between two worlds.
- Watch for dissonance. A game about the cost of time that lets the player spend it freely has told two contradictory stories.

## 2. Stretch the concept

### 2.1 Pain point

Most first concepts land on the same few templates: third-person action, first-person horror, 2D platformer. They are buildable, but the panel sees many of them, and none gives you much to learn.

### 2.2 Concept

Your first idea is usually your safest. Before you commit, write three **concept variants**:

| Variant | Question to ask |
| :- | :- |
| Safe | What would most students submit? |
| Stretched | What one change makes it clearly different? |
| Radical | What would we be surprised to see built? |

To choose between them, use **MDA** (Hunicke, LeBlanc and Zubek, 2004). It splits a game into:

- **Mechanics**: the rules you build.
- **Dynamics**: the behaviour those rules produce when played.
- **Aesthetics**: what the player feels.

Designers work from mechanics outward; players experience the game from aesthetics inward. Name the feeling you want first (dread, tension, wonder, loss, discovery, fellowship), then choose the variant whose mechanics produce it most strongly.

An **amplifier** is a platform, input or social mode that intensifies your theme:

| Amplifier | What it adds | Commercial reference |
| :- | :- | :- |
| VR | Presence, scale, looking and reaching as mechanics | *Half-Life: Alyx* |
| Asymmetric multiplayer | Players with different information or powers | *Keep Talking and Nobody Explodes* |
| Local co-op | Shared screen, shared consequences | *It Takes Two* |
| Audio-led play | Sound as the main source of information | *Hellblade: Senua's Sacrifice* |
| Unusual input | Voice, motion, the controller as an object | *Nintendo Labo* |

The **magic circle** (Huizinga, developed by Salen and Zimmerman, 2004) is the boundary between the game and ordinary life. VR and AR let you play with where that boundary sits.

### 2.3 Mental model

Read it as: *the safe variant is your fallback, not your starting point.* You justify the stretch by the feeling it creates, not by novelty.

### 2.4 Worked example

*Titanfall 2*'s mission "Effect and Cause" takes a standard shooter and adds one rule: the player can jump between the same building in two time periods at will. Enemies in one era cannot reach you in the other.

<!-- IMAGE: "Titanfall 2 Effect and Cause time shift level comparison" -->

- Safe: a corridor shooter in a ruined laboratory.
- Stretched: the same laboratory in two eras, one button to switch.
- Aesthetic: disorientation and cleverness; the player feels they are outwitting the building.

*Dishonored 2*'s "A Crack in the Slab" uses the same idea with a handheld timepiece that lets you peer into the other era before crossing. It is a strong model of two worlds overlapping in one space.

### 2.5 Pitfalls

- An amplifier bolted on is a cost, not a feature. If VR does not strengthen the theme, leave it out.
- Networked multiplayer multiplies testing and debugging. It is allowed, but you must justify it strongly.
- Radical does not mean unbuildable. State the risk and how you would reduce it.

| Risk | Typical examples | Note |
| :- | :- | :- |
| Low | Single-player, local co-op | Well supported |
| Medium | VR on Quest 3 | Department headsets available; supported |
| High | Networked multiplayer | Allowed; justify it strongly |

## 3. Build the character

### 3.1 Pain point

"The player is a soldier." "The main character is a girl who finds a portal." These are costumes. The player learns nothing through play that they did not know from the first screenshot.

### 3.2 Concept

A game character exists through what the player experiences as them. Novelist Monique Roffey builds characters in four quadrants. Adapted for games, each quadrant must produce a **playable consequence**: something the player sees, controls or discovers because of that detail.

| Quadrant | Covers | Playable consequence |
| :- | :- | :- |
| 1. Physical | Age, size, health, strengths, flaws, gait, voice | Movement, camera, physical limits, audio |
| 2. Psychological | Temperament, attitudes, self-knowledge, blind spots | Choices, reactions under pressure, hidden information |
| 3. Interpersonal | Family, allies, rivals, culture, values | NPCs, factions, co-op roles, moral pressure |
| 4. History | Best and worst events in their life | Backstory told through the world |

Roffey's view is that true character shows itself under pressure. In a game, the core mechanic *is* that pressure.

Sum up the character in a **character spine**:

> [Character] wants [X] but is held back by [Y]; the player feels this through [mechanic Z].

### 3.3 Mental model

Read it as: *a limit tells the player more than an ability.* Ask what your mechanic forces the character to do that they would rather not, and what they cannot do at all.

### 3.4 Worked example

*Celeste*'s Madeline is climbing a mountain while struggling with self-doubt.

<!-- IMAGE: "Celeste Madeline climbing mountain pixel art" -->

- Physical: a small climber with limited stamina; the stamina meter is the physical limit made playable.
- Psychological: her doubt becomes a character, Badeline, who the player must chase and confront.
- Spine: Madeline wants to reach the summit but is held back by her own doubt; the player feels this through precise, punishing climbing where failure is frequent and instant.

### 3.5 Pitfalls

- A profile full of hair colour and favourite food is a dossier, not a character. If a detail has no playable consequence, cut it.
- Abilities are not personality. A double jump says nothing about who someone is.
- Check for dissonance here too: does the mechanic make the character act against who you say they are?

## 4. Tell the story through play

### 4.1 Pain point

A strong History quadrant often gets delivered as a three-minute opening cutscene. Players skip it, and the theme never reaches the play.

### 4.2 Concept

Henry Jenkins (2004) describes four ways game spaces carry **narrative architecture**:

| Mode | How it works | Commercial reference |
| :- | :- | :- |
| Evoked | The space recalls a story the player already knows | *American McGee's Alice* |
| Enacted | The story happens through the player's actions | *Journey* |
| Embedded | Story is placed in the world to be found and pieced together | *Gone Home* |
| Emergent | Story arises from systems interacting | *RimWorld* |

The **player–character gap** is the difference between what the player knows and what the character knows. Deciding what each knows first is a strong source of tension.

### 4.3 Mental model

Read it as: *every room is a paragraph.* Decide which mode tells each part of the story, and let the player do the reading.

### 4.4 Worked example

In *Firewatch*, Henry's backstory is told in text before play begins, but his present is told through radio conversations with Delilah, whom the player never sees. The player chooses his replies, so the relationship is enacted. What happened in the forest before he arrived is embedded in notes, objects and places.

<!-- IMAGE: "Firewatch lookout tower forest view" -->

The player–character gap works in both directions: Delilah knows things Henry does not, and the player begins to suspect things before Henry says them aloud.

### 4.5 Pitfalls

- Embedded story that no one finds is not story. Place key fragments on the critical path.
- Emergent story needs systems that interact; one system on its own rarely produces it.
- A narrative mode chosen for convenience can contradict the theme. A story about losing grip on reality told only through tidy journal entries is dissonant.

# Practical exercise

Pick a commercial game you have played recently. In five minutes, write:

1. Its core verb, using the template in Section 1.
2. The result of the substitution test.
3. Its target aesthetic, in one or two words.
4. Its protagonist's character spine.

If you cannot write one of these, that is a useful finding: note which one and why.

4. What is one thing your character cannot do, and would a player notice?

# Summary

You should now be able to:

1. Write a core-verb sentence and apply the substitution test to it.
2. Explain procedural rhetoric and ludonarrative dissonance with a commercial example of each.
3. Generate safe, stretched and radical concept variants and choose between them using a named MDA aesthetic.
4. Judge whether an amplifier strengthens a theme and rate its risk.
5. Build a four-quadrant character profile where every detail has a playable consequence.
6. Write a character spine linking want, obstacle and mechanic.
7. Choose one of Jenkins' four modes to deliver a character's history through play.

# Glossary

| Term | Definition |
| :- | :- |
| Real rules | The actual systems a player interacts with; they work the same regardless of art or story (Juul). |
| Fictional world | The setting, characters and story a game presents; the layer a superficial theme lives in (Juul). |
| Core verb | The main action the player repeats, written as one sentence linking it to the theme. |
| Substitution test | Swapping a concept's theme for another to see which rules stop working. |
| Procedural rhetoric | The argument a game makes through its rules rather than its text or images (Bogost). |
| Ludonarrative dissonance | A conflict between what a game's story says and what its rules reward (Hocking). |
| Concept variants | Safe, stretched and radical versions of a concept, written before choosing one. |
| MDA | Mechanics, Dynamics, Aesthetics: a framework linking the rules you build to what the player feels. |
| Mechanics | The rules and systems the designer builds. |
| Dynamics | The behaviour that emerges when players interact with the mechanics. |
| Aesthetics | The emotional response the player has; in MDA, the target the designer aims for. |
| Amplifier | A platform, input or social mode chosen because it intensifies the theme. |
| Magic circle | The boundary between a game and ordinary life (Huizinga; Salen and Zimmerman). |
| Playable consequence | Something the player sees, controls or discovers because of a character detail. |
| Character spine | One sentence stating what a character wants, what holds them back, and the mechanic that makes the player feel it. |
| Narrative architecture | Jenkins' account of how game spaces carry story: evoked, enacted, embedded and emergent. |
| Player–character gap | The difference between what the player knows and what the character knows. |
